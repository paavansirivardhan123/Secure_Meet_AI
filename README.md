# SecureMeet

Private, invite-only video/audio meeting platform with real-time permissions, scheduling, and notifications.

**Stack:** Spring Boot 3 · Next.js 14 · OpenVidu 2.30 · PostgreSQL 15 · JWT · STOMP/WebSocket

---

## 1. Overview & Agenda

**SecureMeet** is a high-security, invite-only, real-time video/audio conferencing platform designed for organizations that require strict access controls, user auditing, and premium collaboration features. The main agenda of the project is to provide a completely private video meeting space where:
- **Zero Public Sign-ups**: Guest enrollment is strictly controlled by an invite-only token mechanism generated by system administrators.
- **Lobby Knocking & Admission System**: Participant access is heavily managed. Guests must "knock" to request entry, placing them in a waiting lobby. The Host approves or rejects admission in real-time.
- **Scheduled Meeting Locks**: Only the host can initialize or start a scheduled session. Guests trying to connect ahead of the host are held on a waiting page.
- **Real-Time Notification and Invites Layer**: Hosts can invite users by email. When a meeting goes live or is scheduled, invited users instantly receive a premium floating toast alert on their dashboard via WebSockets.
- **Immutable User Identity**: Users cannot change their registration email addresses. Email updates are disabled in the UI and hard-blocked at the database level to prevent domain hijacking and impersonation.
- **Protective User Moderation**: Admins can suspend users or close active meetings. Within rooms, participants can report misbehaving users (instantly kicking them and alerting the admin), but the meeting **Host is fully protected from reports**.
- **Clean Countdown Redirects**: If a host ends a session, all participants are automatically notified and redirected back to the dashboard with an exact 5-second countdown timer.

## 2. Tech Stack

### Backend
- **Framework**: Spring Boot 3 (Java 17)
- **Security**: Spring Security with Stateless JWT Authentication
- **Real-Time Messaging**: Spring WebSocket utilizing the STOMP & SockJS messaging protocol
- **WebRTC Orchestration**: OpenVidu Java Client API
- **Database / ORM**: PostgreSQL 15 with Spring Data JPA (Hibernate)
- **Security Filters**: Bucket4j (Token Bucket rate-limiting filter for login/auth endpoints)
- **Mail integration**: Spring Mail (SMTP integration for sending registration tokens)

### Frontend
- **Framework**: Next.js 14 (App Router & React 18)
- **Styling**: Vanilla CSS alongside TailwindCSS (Tailwind v3 using a customized HSL color palette)
- **State Management**: Zustand (State management store for stateless auth & user profile sessions)
- **API Client**: Axios (Configured HTTP client with request/response interceptors)
- **WebSockets**: SockJS-Client & `@stomp/stompjs`
- **WebRTC Stream Rendering**: OpenVidu Browser library

### Infrastructure & Deployment
- **Containerization**: Docker & Docker Compose
- **Reverse Proxy**: Nginx (handling SSL/TLS termination, static content hosting, WebSocket upgrades, and security headers)

## 4. Key Core Features & Implementation Details

### Dynamic Dashboard Categories
The user dashboard in [dashboard/page.tsx](file:///e:/git_projects/ONGOING_PROJECTS/JAVA/project/frontend/app/dashboard/page.tsx) categorizes meetings into:
1. **Ongoing Meetings**: Real-time active sessions with host names and quick-join controls.
2. **Upcoming Meetings**: Scheduled sessions. Includes custom start buttons for hosts and join buttons for participants.
3. **History**: Past sessions. Displays meeting titles, host names, start/end dates, and the precise meeting duration calculated in the database and formatted as `Xh Ym Zs` or `Ym Zs` (e.g. `2m 45s`).

### Lobby Knocking & Admission Requests
- Non-host participants attempting to join an active session are placed in a wait state.
- A knock request is persisted in the database via `JoinRequest` and sent to the host.
- The host is alerted in real-time through a lobby panel drawer inside the meeting room. The host can click **Accept** or **Decline**.
- Once accepted, the participant receives their OpenVidu connection token and enters the room. If declined, they are redirected to an "Admission Denied" page featuring a **JOIN ongoing meetings** button directing them back to their dashboard.

### Real-Time User Invitations & Toast Notifications
- Meeting creators can invite other registered users via comma-separated email addresses during meeting creation.
- Invited emails are recorded in the `meeting_invitees` database table.
- A real-time STOMP notification is broadcast to target invitees at the destination `/topic/notifications/{email}`.
- Dashboard clients listening to this channel show a premium, floating, visual Toast Alert:
  - **Live Meetings**: Shows a green pulse alert: *“Meeting started by [HostName]: [Title]”* with a **Join Meeting** button.
  - **Scheduled Meetings**: Shows a scheduled alert: *“Upcoming invite: [Title] at [Time]”* with a **View Scheduled** button.
  - Receiving any notification automatically refreshes the dashboard meeting tabs lists in the background.

### User Profile Management
- Users can update their profile metadata, including base64 avatars, phone number, and a bio description, directly on the dashboard.
- Users **cannot edit their email address**. The frontend disables the email input field and displays a contact notice. The backend controller [UserController.java](file:///e:/git_projects/ONGOING_PROJECTS/JAVA/project/backend/src/main/java/com/securemeet/controller/UserController.java) drops the email parameter during profile updates.

### Protected Host Reporting
- Participants can report misbehavior. Submitting a report instantly kicks the reported participant and posts an alert to the administrator's report log.
- To prevent host-sabotage, the **Host cannot be reported** by anyone. The "Report" button is hidden in the frontend for the host, and the backend [MeetingService.java](file:///e:/git_projects/ONGOING_PROJECTS/JAVA/project/backend/src/main/java/com/securemeet/service/MeetingService.java) throws a runtime exception if a report payload specifies the host's ID.

### Clean Exit Screens & Redirects
- When a host terminates a session, all connected clients are instantly disconnected from the WebRTC server and redirected to an `EndedScreen`.
- The `EndedScreen` displays an automated, animated 5-second countdown timer. At `0`, it routes the user back to the dashboard.
- Users can click the manual **JOIN ongoing meetings** button to bypass the countdown.
- All other exit points (Left Room, Kicked from Room, Knock Rejected) feature the same consistent, premium redirect button.

## 5. Quick Start (Local Development)

### Prerequisites
- **Java**: JDK 17 & Maven
- **Node.js**: v20 or later
- **Docker**: Docker Engine & Docker Compose

### 1. Start Infrastructure (Postgres & OpenVidu)
```bash
cd docker
docker compose up -d
```
This runs PostgreSQL on port `5432` and the OpenVidu local WebRTC server on port `4443`.

### 2. Configure and Run the Backend API
```bash
cd backend
mvn clean spring-boot:run
```
The backend API starts on `http://localhost:8080`.
> **Note**: On the first start, the database is auto-migrated, and a default administrator account is generated:
> - **Email**: `admin@securemeet.com`
> - **Password**: `Admin@1234`

### 3. Configure and Run the Frontend Client
```bash
cd frontend
cp .env.local.example .env.local
npm install
npm run dev
```
The client application runs on `http://localhost:3000`.

## 7. API Reference

| Method | Endpoint | Auth | Description |
|--------|----------|------|-------------|
| **POST** | `/api/auth/login` | None | Verify credentials, apply rate limit, and return JWT |
| **POST** | `/api/auth/register` | None | Register a new user using a valid registration token |
| **GET** | `/api/auth/me` | JWT | Get current logged-in user profile details |
| **GET** | `/api/users/profile` | JWT | Fetch current profile metadata |
| **PUT** | `/api/users/profile` | JWT | Update profile details (blocks email changes) |
| **POST** | `/api/sessions/create` | JWT | Schedule or start a meeting and record invitees |
| **POST** | `/api/sessions/join/{sessionId}` | JWT | Submit request to join a meeting (or get token if approved) |
| **POST** | `/api/sessions/report` | JWT | Report a participant (triggers instant kick and alerts admin) |
| **POST** | `/api/sessions/end/{sessionId}` | JWT | Terminate meeting session (Host / Admin only) |
| **GET** | `/api/sessions/dashboard` | JWT | Retrieve categorized user-specific dashboard lists |
| **GET** | `/api/sessions/active` | JWT | Get active meetings list (Admin only) |
| **GET** | `/api/sessions/{sessionId}/requests` | JWT | Fetch pending guest join requests (Host only) |
| **POST** | `/api/sessions/requests/{requestId}/approve` | JWT | Approve guest knocking admission (Host only) |
| **POST** | `/api/sessions/requests/{requestId}/reject` | JWT | Decline guest knocking admission (Host only) |
| **POST** | `/api/chat/send` | JWT | Save and broadcast meeting chat message |
| **GET** | `/api/chat/history/{sessionId}` | JWT | Fetch persistent chat log for a session |
| **POST** | `/api/chat/signal` | JWT | Broadcast hand raise, display name changes, or events |
| **POST** | `/api/admin/invite` | ADMIN | Generate registration token for user invitation |
| **POST** | `/api/admin/invite/email` | ADMIN | Generate registration token and dispatch invite email |
| **GET** | `/api/admin/users` | ADMIN | Retrieve list of all users |
| **PUT** | `/api/admin/users/{userId}/deactivate` | ADMIN | Suspend user |
| **PUT** | `/api/admin/users/{userId}/activate` | ADMIN | Restore user |
| **GET** | `/api/admin/reports` | ADMIN | View persistent abuse report list |

## 8. WebSocket Topics (STOMP)

| Topic Destination | Subscribers | Message Payload | Purpose |
|-------------------|-------------|-----------------|---------|
| `/topic/notifications/{email}` | Registered target user | `NotificationMessage` | Live meeting invite toast alerts |
| `/topic/session/{id}/chat` | Connected meeting participants | `MessageResponse` | Real-time chat dispatch |
| `/topic/session/{id}/signals` | Connected meeting participants | `SignalEvent` | Live hand raises and name updates |
| `/topic/session/{id}/kick` | Connected meeting participants | `KickNotification` | Evicting reported users instantly |
| `/topic/session/{id}/ended` | Connected meeting participants | String notification | Closing room UI on host termination |
| `/topic/session/{id}/lobby` | Session Host | `JoinRequestResponse` | Listing guest knock/admission requests |
| `/topic/session/{id}/join-status/{userId}` | Knocking guest user | Approval Status Map | Real-time notification of lobby decision |
| `/topic/admin/reports` | Admin Dashboard | `ReportNotification` | Dispatching abuse reports to admin |
